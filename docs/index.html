BATON

바통(Baton)은 기존 중고거래 플랫폼의 구조적 문제를 기술로 해결하는 중고거래 서비스입니다.
채팅으로만 이루어지는 가격 협상, 조작 가능한 신뢰 점수, 패널티 없는 약속 파기를 오퍼 시스템 · 행동 기반 신뢰 점수 · 노쇼 감지로 해결합니다.

// 이름의 의미
바통(Baton) = 바로 통하는 거래
            = 릴레이 바통처럼 채팅 합의 → 결제로 흐름을 넘긴다
🎯 왜 만들었나
FROM 당근마켓 커머스팀 소개

"기존 당근의 거래를 신뢰할 수 있는 결제 구조로 전환하고, 스토어를 고객에게 명확히 인식시키고, 당근 스토어만의 정체성과 브랜드 가치를 강화하는 여정의 시작점에 있어요."

기존 플랫폼의 문제바통의 해결 방식
채팅 네고 → 찔러보기 진상, 기록 없음오퍼 시스템 → 모든 협상이 구조화되고 이벤트로 기록됨
매너온도(별점) → 보복 신고로 조작 가능행동 데이터 기반 신뢰 점수 → 시스템이 자동 계산
노쇼 시 비매너 신고 한 번 → 실질 제재 없음노쇼 누적 → 점수 차감 + 기능 자동 제한
사기 탐지 AI 오작동 → 정상 판매자 피해행동 패턴 기반 룰 엔진 → 오탐율 감소
⚡ 핵심 기능
FEAT 01
구조화된 오퍼 시스템
채팅 네고를 오퍼 객체로 구조화. 모든 협상이 이벤트로 기록되고, 수락 시 거래 예약 자동 생성. 취소 시 신뢰 점수 반영.
FEAT 02
행동 기반 신뢰 점수
별점 대신 응답률·약속이행률·취소율·신고이력을 가중치 기반으로 자동 계산. 점수 구간별 오퍼 기능 제한.
FEAT 03
거래 예약 + 노쇼 감지
오퍼 수락 시 예약 자동 생성. 30분 전 알림 발송. 노쇼 누적 시 점수 차감 + 기능 자동 제한.
FEAT 04
커머스 코어 (개발 환경)
결제 멱등성·셀러 정산 배치는 피처 플래그로 프로덕션 비활성화. 아키텍처 완성도와 기술 역량 증명용으로 구현.

🔧 핵심 기술 구현
① 동시성 제어 — 3단 방어 구조
PROBLEM

동일 오퍼에 여러 구매자가 동시에 수락 요청을 보내는 경우, 단 한 건만 처리되어야 합니다.

Kotlin 3단 방어 — Redis 분산 락 → JPA 낙관적 락 → MySQL Row-level 락
fun acceptOffer(offerId: OfferId, sellerId: UserId) {
    // 1단: Redis 분산 락
    val lock = redisson.getLock("offer:${offerId.value}:lock")
    lock.lock(5, TimeUnit.SECONDS)
    try {
        val offer = loadOfferPort.load(offerId)   // 2단: @Version 낙관적 락
        val accepted = offer.accept(sellerId)     // 도메인 상태 전환
        saveOfferPort.save(accepted)              // 3단: MySQL Row-level 락
        publishOfferEventPort.publish(OfferAcceptedEvent(accepted))
    } finally { lock.unlock() }
}

③ 결제 멱등성 — 이중 결제 원천 차단 (개발 환경)
Kotlin UUID 멱등키 기반 중복 결제 방지
fun processPayment(request: PaymentRequest): PaymentResult {
    // 1. 중복 요청 체크 (Redis)
    val cached = redis.get("payment:${request.idempotencyKey}")
    if (cached != null) return cached  // 동일 요청 → 캐시 반환

    // 2. 분산 락으로 동시 요청 차단
    val lock = redisson.getLock("lock:${request.idempotencyKey}")
    lock.lock()
    try {
        val result = pgClient.pay(request)
        redis.set("payment:${request.idempotencyKey}", result, TTL_24H)
        return result
    } finally { lock.unlock() }
}
④ 신뢰 점수 캐싱 — Redis + 비동기 재계산
Kotlin 캐시 히트 우선, 이벤트 수신 시 비동기 재계산
fun getScore(userId: UserId): TrustScore {
    // 1. Redis 캐시 우선 조회
    val cached = cacheAdapter.get(userId)
    if (cached != null) return cached

    // 2. DB 계산 후 캐시 저장 (TTL 1h)
    val score = calculateFromDb(userId)
    cacheAdapter.set(userId, score, Duration.ofHours(1))
    return score
}

// Kafka Consumer: 이벤트 수신 시 캐시 무효화 → 재계산 트리거
@KafkaListener(topics = ["baton.reservation.reservation.no-showed"])
fun handleNoShow(event: NoShowEvent) {
    cacheAdapter.evict(event.userId)  // 캐시 무효화
    trustScoreService.applyPenalty(event.userId, PenaltyReason.NO_SHOW)
}
